## Questions

1. Finding 1: fix it in this round (one line in a new `save_model` plus a test), or is "a hung run still owns the
   paper forever" a deliberate reading of the 15-minute default? The contract's decision note only says the
   timeout stays, not what a timed-out run may still do.
2. Should a discarded stale run also write its message into `generation_error`? Today it only notifies and
   audits, so the page shows nothing. The current behaviour looks right (the error belongs to the old run, and
   writing it would confuse the newer one), but it is worth confirming it was a choice.
3. Untracked files unrelated to this task are in the working tree: `.mcp.json`, `docs/design/`,
   `docs/spec-status-2026-11-03.md`, `for testing the q generation feature.txt`. Make sure they aren't staged
   with this commit. The repo is public.

## Done well

- The token is read back from the database after the claim instead of trusting the in-memory `timezone.now()`.
  That is the detail this whole design stands on, and it is the one most people get wrong.
- Both ownership checks are inside the row lock that already existed and ahead of every destructive write, so
  no new lock and no new lock ordering was introduced.
- `_run_and_report` turns the clear into a conditional `UPDATE ... WHERE generation_started_at = token` rather
  than reading-then-writing, so it is correct without holding a lock at all.
- Refusing the POST in words and *then* redirecting, instead of letting the read-only permission produce a bare
  403, is the right call for school staff — and it is placed after the button branch, so it didn't break the
  existing regenerate/lock refusals.
- `has_change_permission` returning False closes the real corruption window that finding 3 describes: while a
  run holds the paper, the admin's full-row save can no longer clobber `check_summary` / `model_used`.
- `lock_final` syncing the three lock fields back onto the caller's object is a small touch that keeps the
  admin page honest after the redirect, and the docstring explains *why* the re-read exists.
- The new tests assert the things that actually matter (question texts, the surviving token, `generation_error`,
  `controller_notes`, the notification) rather than just "no exception".
